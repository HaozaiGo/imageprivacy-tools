Testing methodology

How we test image privacy tools and their limits.

A successful download is not proof that an image is safe to publish. ImagePrivacy separates hidden metadata, visible private details, output quality, and network behavior into checks that can be repeated with disposable sample files.

Maintained by ImagePrivacy · Last reviewed October 20, 2026 · Current reference browser: Chrome 155 on macOS

Our disposable sample set

Tests use images created for this site rather than personal photos. The set includes a JPEG with harmless EXIF fields, a PNG screenshot with invented account details, a transparent image, a high-resolution gradient, and an HEIC sample. No customer file is needed. Originals are kept separate so every exported copy can be compared with the same source.

Local-processing verification

We open DevTools, clear the Network panel, disable cache, select the sample, perform the edit, and download the result. Requests for application code or analytics are recorded separately from file transmission. A local-processing claim passes only when file bytes and rendered output stay inside the browser runtime. We repeat the check after reloading so cached requests do not hide an upload.

Metadata is checked after export

Canvas-based export commonly creates a metadata-light derivative, but assumptions are not enough. We reopen the downloaded file with the EXIF inspector and compare metadata categories. The review records whether GPS, camera, software, orientation, and date fields remain. A clean report applies to that exported copy only, not to the private original or a file produced by another application.

Visible privacy is a separate human review

Automated metadata checks cannot identify every face, shipping label, reflection, browser tab, QR code, document ID, or background screen. For redaction, we inspect the flattened export at normal size and at 100% zoom. High-risk details should use an opaque box rather than blur, because blur and pixelation can preserve shapes and context.

Quality and compatibility checks

We compare dimensions, file size, transparency, orientation, text edges, gradients, and color appearance in the downloaded file. JPEG and WebP quality sliders are encoder controls, not universal scores. HEIC support depends on the browser decoder, so one representative file must be tested in the real destination before a batch is converted.

Failure paths, accessibility, and mobile

Each tool is checked with an unsupported file, an empty selection, repeated actions, download controls, keyboard navigation, language switching, and a 390 CSS pixel viewport. Errors should explain the next step without presenting an advertisement as a download or result control. Upload regions, previews, and controls must remain readable without horizontal scrolling.

Corrections and repeatability

Important tool or guide changes are listed in the public changelog. To report a reproducible issue, include the tool URL, browser version, input format and dimensions, expected result, and actual result. Do not email a private source image; create a harmless sample or describe the failure at contact@imageprivacy.org.
